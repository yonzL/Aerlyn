# 设计原则与取舍

Aerlyn Wire 的设计目标不是“把所有远程桌面功能塞进一个库”，而是提供一个可审计、可替换传输、可被宿主安全使用的协议核心。

## 原则

1. **纯核心**：线格式、状态机、窗口、分片、协商与纯算法在 crate 内；socket、线程、编码器、文件系统在外部。
2. **显式边界**：`MessageIo` 是唯一传输 SPI；异步、TCP、优先级、DATAGRAM 属于外部 `Transport` 扩展。
3. **显式上限**：每个可变长字段都有字节/数量上限；不依赖“对端不会发大包”。
4. **单一权威**：线格式只在 `architecture/protocol.md` 定义；历史设计档案不覆盖当前规范。
5. **版本克制**：1.x 不做版本协商；2.0.0 才处理与 1.0.0 的兼容；发布版本与 wire 版本分离。
6. **可测试性**：纯逻辑用内存连接与属性/边界测试；传输适配器单独做真实 I/O 测试。

## 关键取舍

| 取舍 | 选择 | 理由 |
|---|---|---|
| 传输 | 只定义 `MessageIo` | 让 QUIC/TCP/内存/测试替身都能复用同一状态机 |
| 控制面 | JSON + 类型注册表 | 可读、可演进；二进制平面承担高吞吐 |
| 视频 | 可靠流分片 + DATAGRAM/FEC | 兼顾完整性与低延迟；由宿主选择路径 |
| 文件 | credit + 位图 + 块级摘要 | 支持续传与并发；压缩/落盘留给宿主 |
| 音频 | 抖动缓冲 + RED + 时钟漂移 | 协议只做时序与恢复，不做编解码 |
| 版本 | 单值 `version`，1.x 不协商 | 避免未经验证的降级路径；2.0 再引入协商 |
